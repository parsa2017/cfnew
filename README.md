CFnew Minimal Core






Keep proxy forwarding on Cloudflare, while delegating the console, address optimization, and subscription generation to a separate panel. The core is 37,806 bytes, approximately 92% smaller than the original full version. Node traffic connects directly to your own Worker.


Open Panel · Download Latest Release · Video Tutorial · Complete Variables Reference


The current default branch is core-only. The previous full version remains available on main, and its previous release is v3.1. The standalone panel source code is available at cfnew-panel.


Connecting the Panel and Clients




Open cfnew.xy.kg and enter your own Worker domain and the same UUID. Enter the HTTPS root address without a UUID, path, or query parameters.


In Configuration Management, select the protocol, preferred-address sources, outbound method, and other options, then click Save. Without a KV binding, you can read environment configuration and generate subscriptions, but cannot save settings online.


Copy the subscription URL generated by the panel and import it into the appropriate client. The subscription domain belongs to the panel, while the node's SNI / Host and actual proxy endpoint remain your Worker.




You can also deploy the panel yourself. Vercel deployment instructions and the optional w variable are documented in that repository. Set w in the panel project, not in the Worker.


Your UUID, custom path, and complete subscription URL can all be used to access your configuration. Keep them secure. "Remember Node" is stored only in the current browser. Deleting a saved node does not delete the Worker or KV configuration.

First Deployment


Prepare a Cloudflare account and generate your own UUID. Replace all example domains and credentials with your own.


Cloudflare Pages




Download Pages.zip above.


In the Cloudflare dashboard, go to Workers & Pages → Create Application → Pages → Direct Upload / Upload Assets. Create a project, upload the entire Pages.zip, and deploy it.


Go to Project Settings → Variables and Secrets. Add a text variable named u in the Production environment and enter your UUID. Uppercase U is also supported.


If you want to save settings through the panel, create a Workers KV namespace and add it under the Pages project's bindings. Set the binding name to C or c.


Set the compatibility date to 2026-01-20. After adding variables, bindings, or changing the compatibility date, redeploy so the new settings take effect in production.


Use the accessible pages.dev address or bind your own domain to the project, then connect the panel using the instructions above.




If the Pages interface only allows folder uploads, extract the archive and upload the directory containing _worker.js. Make sure _worker.js is located at the root of the uploaded content.


Cloudflare Workers




Create a new Worker, complete the initial deployment, and then open the code editor.


Download _worker.js and paste its entire contents into the editor. Use ES Module format and preserve import and export default. Save and deploy. Do not copy the HTML from the GitHub webpage.


Under Settings → Variables and Secrets, add u with your UUID. If you need to save settings online, add a KV binding named C or c.


Set the compatibility date to 2026-01-20, redeploy, and bind an accessible domain.




Seeing hello on the Worker homepage is the expected behavior for this version. The management interface and subscriptions have moved to the standalone panel and are no longer hosted on the Worker homepage.

Address optimization only changes the endpoint address used by the client. The node's Host / SNI still uses your Worker domain. Availability of third-party ProxyIP addresses, online optimization sources, subscription conversion services, and residential nodes depends on their respective providers.


How to Enter Preferred Addresses


Preferred domains, preferred IPs, and repository-based optimization are enabled by default. IPv4 / IPv6 and three-network filtering are also enabled by default. Manually entered addresses take priority when a manual list is available.


104.16.1.1:443#Manual IPv4
[2606:4700::1111]:8443#Manual IPv6
edge.example.com:443#Manual domain



Use one address per line. English commas are also supported. Ports are preserved in subscriptions. IPv6 addresses with ports must be enclosed in square brackets. The addresses above are examples of the required format and do not guarantee connectivity from your location.


Enter an online list URL in yxURL and enable "Repository Optimization". You can retrieve the online list, filter and test addresses, and then overwrite or append the selected results when saving.


Testing is initiated by the panel server and uses your Worker domain as Host / SNI. The displayed latency reflects the panel server's perspective. Actual performance should be tested on your client. Online IPv6 testing from Vercel may be affected by platform outbound restrictions; this does not necessarily mean that IPv6 nodes are unavailable.


The manual preferred-address list has a maximum size of 262144 characters, and configuration request bodies are limited to 1 MiB. Use an online URL for larger lists.


Custom Path Login


After setting d=/Admin/Panel, enter /Admin/Panel or Admin/Panel in the second field of the public panel. Multi-level paths, Chinese characters, and leading or trailing slashes are supported. Letter case must match exactly.


After successful login, the panel retrieves the actual proxy UUID and uses it to generate stable endpoints. Therefore, changing d does not invalidate UUID subscriptions that have already been copied. d is the management entry path, while tp is used for the Trojan password and XHTTP compatibility path. They serve different purposes. UUID and custom-path interfaces can be used simultaneously.


If an older core does not support custom-path login, log in using the UUID first and then update _worker.js.


Free CPU Protection


Added in the matching version 2026.10.17.2, this feature is disabled by default. You can enable and save it in the panel, or set the Worker variable to freeCpu=yes / FREE_CPU=yes. Settings saved in KV take priority.


When enabled, each individual connection shares a download budget of 384 KiB / 96 data chunks. Exceeding either limit causes the connection to be actively terminated. The client must reconnect. The budget is recalculated for each new connection, and outbound retries do not reset the current budget. Changes to this setting apply to new connections.


This is a traffic and processing-count budget. It cannot guarantee zero CPU limit overruns on free accounts. Downloads, video playback, and long-lived connections may be interrupted, and automatic resumption is not guaranteed. The panel will prompt you to upgrade if the old core does not support this feature.


Upgrading from the Previous Full Version




Back up your existing Worker code and note your original u, KV binding, domain, and compatibility date.


Upload this version's _worker.js or Pages.zip. Keep your original UUID and KV binding, set the compatibility date to 2026-01-20, and redeploy.


Open the standalone panel and log in using your original domain and UUID. Confirm that your saved settings are still available.


Copy the new subscription generated by the panel into your client again. The old https://Worker-domain/UUID/sub or Worker /sub URLs no longer generate subscriptions.


Check protocol and client compatibility. This version uses stream-one for XHTTP. Re-select unsupported legacy protocols in the panel.




Uploading the core does not automatically clear KV. Keep your old code before switching so you can upload it again to roll back. When reverting to the full version, also restore that version's subscription entry point.


When the panel and core are on the same version, no update notification is displayed. If their versions differ, or the old core has no version marker, the panel displays both versions and their download links.


Frequently Asked Questions




Issue
What to Check First




The Worker homepage only displays hello
This is normal. Log in through the standalone panel.


The panel cannot connect / authentication fails
Check whether the domain is publicly accessible, whether u has been deployed, and whether the UUIDs match. Check capitalization for custom paths. Cloudflare Access or CAPTCHA challenges can block API requests.


Subscriptions can be generated, but saving fails
Check whether KV is bound as C or c, whether it is bound to the production environment, and whether you redeployed after binding it.


Environment variable changes do not take effect
Redeploy first, then check whether an existing KV configuration with the same name is overriding it.


The old Worker subscription URL no longer works
Copy the subscription URL again from the standalone panel.


The client subscription returns hello / HTML
Check whether you are using the Worker homepage or whether Vercel login protection is blocking the panel.


XHTTP does not work
Enable ex, use a compatible client, and keep HTTP/2 with stream-one.


Downloads disconnect after a while
Check Free CPU protection. When enabled, it actively terminates connections after the budget is reached.


Pages upload fails
Use the release's Pages.zip, not the entire source archive. If extracting it, verify that _worker.js is at the root directory.
