هسته مینیمال CFnew






عملیات انتقال پروکسی را روی Cloudflare نگه دارید و مدیریت پنل، بهینه‌سازی آدرس‌ها و تولید اشتراک را به یک پنل مستقل بسپارید. حجم هسته فقط ۳۷٬۸۰۶ بایت است که در مقایسه با نسخه کامل اصلی حدود ۹۲٪ کاهش یافته است. ترافیک نودها مستقیماً به Worker اختصاصی خودتان متصل می‌شود.


باز کردن پنل · دانلود آخرین نسخه · آموزش ویدئویی · فهرست کامل متغیرها


شاخه پیش‌فرض فعلی core-only است. نسخه کامل قدیمی همچنان در شاخه main موجود است و انتشار قدیمی آن v3.1 است. کد منبع پنل مستقل در مخزن cfnew-panel قرار دارد.


اتصال پنل و کلاینت‌ها


۱. وارد cfnew.xy.kg شوید و دامنه Worker خودتان و همان UUID را وارد کنید. دامنه باید آدرس اصلی HTTPS باشد و نباید شامل UUID، مسیر یا پارامترهای جست‌وجو باشد.


۲. در بخش مدیریت تنظیمات، پروتکل، منابع آدرس‌های بهینه، روش اتصال خروجی و سایر گزینه‌ها را انتخاب کنید و روی ذخیره بزنید. اگر KV متصل نباشد، می‌توانید تنظیمات محیط را بخوانید و اشتراک تولید کنید، اما امکان ذخیره آنلاین تنظیمات وجود ندارد.


۳. آدرس اشتراکی را که پنل تولید کرده کپی کنید و در کلاینت مناسب وارد کنید. دامنه اشتراک متعلق به پنل است، اما SNI / Host نود و ورودی واقعی پروکسی همچنان دامنه Worker خودتان خواهد بود.


همچنین می‌توانید پنل را شخصاً مستقر کنید. مراحل استقرار روی Vercel و متغیر اختیاری w در همان مخزن توضیح داده شده‌اند. متغیر w باید در پروژه پنل تنظیم شود، نه در Worker.


UUID، مسیر سفارشی و لینک کامل اشتراک همگی امکان دسترسی به تنظیمات شما را فراهم می‌کنند؛ بنابراین آن‌ها را محرمانه نگه دارید. گزینه «به‌خاطر سپردن نود» فقط در مرورگر فعلی ذخیره می‌شود. حذف نود ذخیره‌شده، Worker یا تنظیمات KV را حذف نمی‌کند.

Cloudflare Pages


۱. فایل Pages.zip را از لینک بالا دانلود کنید.


۲. در داشبورد Cloudflare به مسیر Workers & Pages → Create Application → Pages → Direct Upload / Upload Assets بروید. یک پروژه بسازید، کل فایل Pages.zip را آپلود کنید و آن را Deploy کنید.


۳. وارد Project Settings → Variables and Secrets شوید. در محیط Production یک متغیر متنی با نام u اضافه کنید و UUID خودتان را در آن قرار دهید. نام بزرگ U نیز پشتیبانی می‌شود.


۴. اگر می‌خواهید تنظیمات را از طریق پنل ذخیره کنید، یک فضای نام Workers KV بسازید و آن را در بخش Bindings پروژه Pages اضافه کنید. نام Binding باید C یا c باشد.


۵. تاریخ سازگاری را روی 2026-01-20 تنظیم کنید. پس از اضافه‌کردن متغیرها، Bindingها یا تغییر تاریخ سازگاری، دوباره Deploy کنید تا تنظیمات جدید وارد نسخه Production شوند.


۶. از آدرس قابل‌دسترسی pages.dev استفاده کنید یا دامنه اختصاصی خودتان را به پروژه متصل کنید. سپس طبق مراحل بالا پنل را متصل کنید.


اگر صفحه Pages فقط اجازه آپلود پوشه را می‌دهد، فایل فشرده را استخراج کنید و پوشه‌ای را آپلود کنید که _worker.js داخل آن قرار دارد. مطمئن شوید این فایل در ریشه محتوای آپلودشده باشد.


Cloudflare Workers


۱. یک Worker جدید بسازید، استقرار اولیه را کامل کنید و سپس وارد ویرایشگر کد شوید.


۲. فایل _worker.js را دانلود کنید و تمام محتوای آن را در ویرایشگر قرار دهید. از قالب ES Module استفاده کنید و import و export default را حفظ کنید. فایل را ذخیره و Deploy کنید. کد HTML صفحه GitHub را کپی نکنید.


۳. در بخش Settings → Variables and Secrets متغیر u را اضافه کنید و UUID خودتان را در آن قرار دهید. برای ذخیره آنلاین تنظیمات، یک KV Binding با نام C یا c اضافه کنید.


۴. تاریخ سازگاری را روی 2026-01-20 تنظیم کنید، دوباره Deploy کنید و یک دامنه قابل‌دسترسی به Worker متصل کنید.


نمایش عبارت hello در صفحه اصلی Worker رفتار مورد انتظار این نسخه است. صفحه مدیریت و اشتراک‌ها به پنل مستقل منتقل شده‌اند و دیگر در صفحه اصلی Worker قرار ندارند.

قابلیت
پشتیبانی فعلی




ورودی پروکسی
VLESS WebSocket، Trojan WebSocket، VLESS XHTTP.


XHTTP
HTTP/2 با استفاده از stream-one؛ آن را به packet-up یا stream-up تغییر ندهید. سازگاری auto نیز در این نسخه تضمین نمی‌شود.


خروجی
اتصال مستقیم، جایگزینی با ProxyIP، SOCKS5، HTTP و HTTPS.


DNS
انتقال DNS از طریق UDP برای VLESS؛ تونل عمومی UDP، UDP بازی یا تونل QUIC ارائه نمی‌شود.


قالب‌های اشتراک
Base64 / V2Ray، Clash، Stash، sing-box، Surge، Loon و Quantumult X، متناسب با هر کلاینت.


زنجیره IP خانگی
با فعال‌کردن jk از اشتراک «CLASH خانگی» پنل استفاده کنید. این قابلیت به نودهای خارجی وابسته است و سرعت و دسترس‌پذیری آن تغییر می‌کند.




sing-box از قالب تنظیمات نسخه 1.12 به بالا استفاده می‌کند. پروتکل‌های قابل‌استفاده در کلاینت‌های مختلف متفاوت هستند؛ بنابراین تا حد امکان از ورودی متناسبی که پنل ارائه می‌دهد استفاده کنید. هسته مینیمال از ورودی Shadowsocks پشتیبانی نمی‌کند.




کلاینت
روش فعال‌سازی پروتکل




Surge
مقدار et=yes را فعال کنید. اشتراک فعلی Surge فقط Trojan تولید می‌کند. اگر به‌صورت پیش‌فرض فقط VLESS فعال باشد، هیچ نود پروکسی تولید نخواهد شد.


Clash / Mihomo، sing-box، Loon، Quantumult X
هنگام استفاده از VLESS، مقدار ev=yes را حفظ کنید. این قالب‌ها منابع XHTTP را به WS تبدیل می‌کنند. فعال‌کردن فقط ex و غیرفعال‌کردن ev باعث می‌شود نودهای VLESS تولیدشده قابل‌استفاده نباشند.


کلاینت‌های سازگار با XHTTP
مقدار ex=yes را فعال کنید، از طریق لینک اشتراک Base64 / VLESS وارد کنید و HTTP/2 و stream-one را حفظ کنید.




بهینه‌سازی آدرس فقط آدرس ورودی مورد استفاده کلاینت را تغییر می‌دهد. Host / SNI نود همچنان از دامنه Worker شما استفاده می‌کند. دسترس‌پذیری ProxyIPهای شخص ثالث، منابع آنلاین بهینه‌سازی، سرویس‌های تبدیل اشتراک و نودهای خانگی به ارائه‌دهندگان مربوطه بستگی دارد.


نحوه واردکردن آدرس‌های بهینه


دامنه‌های بهینه، IPهای بهینه و بهینه‌سازی مخزن به‌صورت پیش‌فرض فعال هستند. فیلتر IPv4 / IPv6 و فیلتر سه اپراتور شبکه نیز به‌صورت پیش‌فرض فعال‌اند. اگر فهرست دستی وجود داشته باشد، ابتدا از همان استفاده می‌شود.


104.16.1.1:443#Manual IPv4
[2606:4700::1111]:8443#Manual IPv6
edge.example.com:443#Manual domain



هر خط باید شامل یک آدرس باشد. جداکردن آدرس‌ها با ویرگول انگلیسی نیز پشتیبانی می‌شود. پورت‌ها در اشتراک حفظ می‌شوند. برای IPv6 همراه با پورت، استفاده از کروشه الزامی است. آدرس‌های بالا فقط نمونه قالب هستند و تضمین نمی‌کنند که از موقعیت جغرافیایی شما قابل‌اتصال باشند.


آدرس فهرست آنلاین را در yxURL وارد کنید و گزینه «بهینه‌سازی مخزن» را فعال کنید. سپس می‌توانید فهرست آنلاین را دریافت کنید، آدرس‌ها را فیلتر و آزمایش کنید و نتایج انتخاب‌شده را هنگام ذخیره جایگزین فهرست قبلی یا به آن اضافه کنید.


آزمایش از سمت سرور پنل انجام می‌شود و دامنه Worker شما به‌عنوان Host / SNI استفاده می‌شود. تأخیر نمایش‌داده‌شده، مربوط به دیدگاه سرور پنل است. عملکرد واقعی باید از طریق کلاینت آزمایش شود. آزمایش آنلاین IPv6 از طریق Vercel ممکن است تحت تأثیر محدودیت‌های خروجی پلتفرم قرار بگیرد؛ این موضوع لزوماً به معنی غیرقابل‌استفاده بودن نودهای IPv6 نیست.


حداکثر اندازه فهرست دستی آدرس‌های بهینه ۲۶۲۱۴۴ کاراکتر و حداکثر اندازه بدنه درخواست تنظیمات ۱ MiB است. برای فهرست‌های بزرگ‌تر از URL آنلاین استفاده کنید.


ورود با مسیر سفارشی


پس از تنظیم d=/Admin/Panel، در فیلد دوم پنل عمومی مقدار /Admin/Panel یا Admin/Panel را وارد کنید. مسیرهای چندسطحی، حروف چینی و اسلش در ابتدا یا انتهای مسیر پشتیبانی می‌شوند. بزرگی و کوچکی حروف باید دقیقاً یکسان باشد.


پس از ورود موفق، پنل UUID واقعی پروکسی را دریافت می‌کند و با استفاده از آن، ورودی‌های ثابت تولید می‌کند. بنابراین تغییر d باعث ازکارافتادن اشتراک‌های UUID که قبلاً کپی کرده‌اید نمی‌شود. d مسیر ورود مدیریتی است، درحالی‌که tp برای رمز Trojan و مسیر سازگاری XHTTP استفاده می‌شود. کاربرد این دو متفاوت است. رابط UUID و مسیر سفارشی می‌توانند هم‌زمان استفاده شوند.


اگر هسته قدیمی از ورود با مسیر سفارشی پشتیبانی نمی‌کند، ابتدا با UUID وارد شوید و سپس _worker.js را به‌روزرسانی کنید.


محافظت از Free CPU


این قابلیت در نسخه هماهنگ 2026.10.17.2 اضافه شده و به‌صورت پیش‌فرض غیرفعال است. می‌توانید آن را در پنل فعال و ذخیره کنید یا متغیر Worker را روی freeCpu=yes / FREE_CPU=yes قرار دهید. تنظیمات ذخیره‌شده در KV اولویت دارند.


پس از فعال‌سازی، هر اتصال مستقل دارای بودجه دانلود مشترک ۳۸۴ KiB / ۹۶ قطعه داده است. عبور از هرکدام از این دو محدودیت باعث قطع فعال اتصال می‌شود و کلاینت باید دوباره متصل شود. محاسبه بودجه برای هر اتصال جدید از ابتدا انجام می‌شود و تلاش مجدد برای اتصال خروجی، بودجه فعلی را بازنشانی نمی‌کند. تغییر این گزینه روی اتصال‌های جدید اعمال می‌شود.


این قابلیت محدودیتی برای حجم ترافیک و تعداد عملیات پردازشی است و نمی‌تواند صفر بودن عبور از محدودیت CPU در حساب‌های رایگان را تضمین کند. دانلودهای در حال انجام، پخش ویدئو و اتصال‌های طولانی ممکن است قطع شوند و ادامه خودکار آن‌ها نیز تضمین نمی‌شود. اگر هسته قدیمی این قابلیت را نداشته باشد، پنل درخواست به‌روزرسانی را نمایش می‌دهد.


ارتقا از نسخه کامل قدیمی


۱. از کد Worker فعلی نسخه پشتیبان تهیه کنید و مقدار u، اتصال KV، دامنه و تاریخ سازگاری قبلی را یادداشت کنید.


۲. فایل _worker.js یا Pages.zip این نسخه را آپلود کنید. UUID و KV Binding قبلی را حفظ کنید، تاریخ سازگاری را روی 2026-01-20 قرار دهید و دوباره Deploy کنید.


۳. پنل مستقل را باز کنید و با دامنه و UUID قبلی وارد شوید. بررسی کنید که تنظیمات ذخیره‌شده همچنان وجود دارند.


۴. اشتراک جدید تولیدشده توسط پنل را دوباره در کلاینت کپی کنید. آدرس‌های قدیمی https://Worker-domain/UUID/sub یا مسیر /sub در Worker دیگر اشتراک تولید نمی‌کنند.


۵. سازگاری پروتکل و کلاینت را بررسی کنید. این نسخه برای XHTTP از stream-one استفاده می‌کند. پروتکل‌های قدیمی ناسازگار را باید دوباره در پنل انتخاب کنید.


آپلود هسته باعث پاک‌شدن خودکار KV نمی‌شود. پیش از تغییر، کد قدیمی را نگه دارید تا در صورت نیاز بتوانید برای بازگشت، آن را دوباره آپلود کنید. هنگام بازگشت به نسخه کامل نیز باید ورودی اشتراک همان نسخه را بازیابی کنید.


اگر پنل و هسته هم‌نسخه باشند، اعلان به‌روزرسانی نمایش داده نمی‌شود. اگر نسخه‌ها متفاوت باشند یا هسته قدیمی نشانگر نسخه نداشته باشد، پنل نسخه هر دو را همراه با لینک دانلود نمایش می‌دهد.

آدرس اشتراک قدیمی Worker کار نمی‌کند
آدرس اشتراک را دوباره از پنل مستقل کپی کنید.


اشتراک کلاینت عبارت hello یا HTML برمی‌گرداند
بررسی کنید که از صفحه اصلی Worker استفاده نکرده باشید یا محافظت ورود Vercel مانع دسترسی پنل نشده باشد.


XHTTP کار نمی‌کند
ex را فعال کنید، از کلاینت سازگار با این پروتکل استفاده کنید و HTTP/2 و stream-one را حفظ کنید.


دانلود پس از مدتی قطع می‌شود
محافظت Free CPU را بررسی کنید. در صورت فعال‌بودن، با رسیدن به بودجه اتصال را به‌صورت فعال قطع می‌کند.


آپلود Pages ناموفق است
از Pages.zip منتشرشده استفاده کنید، نه کل بسته کد منبع. اگر فایل را استخراج کرده‌اید، بررسی کنید _worker.js در ریشه پوشه قرار داشته باشد.

یادداشت‌های کامل انتشار این نسخه · تمام نسخه‌های منتشرشده.


در این به‌روزرسانی، مستندات و ورودی‌های انتشار تکمیل شده‌اند. کد هسته پروکسی در همان نسخه باقی مانده است. تغییر شاخه پیش‌فرض، Workerهایی را که قبلاً Deploy شده‌اند به‌صورت خودکار تغییر نمی‌دهد.




توسعه‌دهندگان پس از به‌روزرسانی شاخه core-only می‌توانند برای بررسی و بسته‌بندی نسخه، دستور زیر را اجرا کنند:


python3 scripts/package-release.py --output dist --tag v2026.10.17.2



این اسکریپت نسخه هسته را بررسی می‌کند و مطمئن می‌شود pages.zip موجود در مخزن با _worker.js مطابقت دارد؛ سپس فایل‌های Pages.zip، _worker.js و SHA256SUMS.txt را تولید می‌کند. پس از Push کردن یک Tag با نسخه هماهنگ v20*، گردش‌کار این شاخه انتشار جدید را ایجاد می‌کند. یادداشت‌های هر نسخه در مسیر docs/releases/version-number.md قرار می‌گیرند. برای هسته جدید در شاخه قدیمی main تگ انتشار ایجاد نکنید.
